# Engineering Component Library

Open **Window > Component Library**. Its local menu uses the existing CreationDock docking/floating
controls. The browser has a category tree, multiword name/manufacturer/model/part-number search,
manufacturer/origin/geometry/chemistry filters, a component list, engineering details and an OCCT preview.
Commercial records and custom records are labeled separately. Categories come only from actual records.

## Research coverage

The bundled seed is generated by the production `.xlsx` importer from the two supplied 2026-10-20
workbooks. Their Google Drive originals remain unchanged. First use creates a local JSON catalog at
`%APPDATA%/DjehutiCAD/component-library.json`; later startup does not access Google Drive or Excel.
`--component-library <absolute JSON path>` selects a separate catalog for portable use or diagnostics.

| Source table | Records | Geometry available |
|---|---:|---|
| Robot Components | 32 | 23 envelopes, 2 simplified outer cylinders, 7 catalog-only records |
| Commercial Battery Packs | 43 | 43 envelopes |

The seven incomplete records are RC-012 through RC-018. RC-019 and RC-020 document their outer diameter
and overall length and receive cylinders without invented shafts or mounting details. Other complete
records receive overall boxes. For proxies, X=width, Y=height, Z=length. Inclined rail ends, extrusion
slots, terminals, mounting holes and internals are not inferred.

Existing research contains no individual bearings, standalone gearboxes or hardware records with enough
product identity to import: those are research leads. No empty categories are created. The 29 material
reference rows are not promoted into a competing materials database or falsely completed isotropic
materials. Read Me, material/reference tables and research leads are reported as skipped component
tables. Matching source-register attribution is retained on component records.

Each record preserves manufacturer, model, part number, source record ID, every source column label and
typed value, cached formula value/formula, source URL, workbook/sheet/row and matching source-register
entries. Declared engineering units are normalized alongside the originals. Missing values remain
unknown; formulas are not executed by the importer. Specification-conflict and data-review notes stay
visible. Catalog data is a research snapshot and is not silently supplemented from the web.

**Import workbook...** accepts the researched Robot Components and Commercial Battery Packs column
schemas or portable component JSON. It validates the complete header/unit layout, supports prefixed
and default XML namespaces, shared/inline strings and sparse cells, and reports new, unchanged, invalid,
skipped and conflicting records. Stable identities use manufacturer plus part number/model. Reimporting
the same source is safe. Source changes retain existing records until **Replace import conflicts...**
is explicitly accepted; unrelated local edits survive. Reload is required after external catalog edits.
Imports use bounded ZIP/XML reads and do not run macros, external links or formulas.

## Geometry and document authority

`CadComponentLibrary` owns application templates. `CadDocument` owns inserted definitions and occurrences.
One frozen definition record and its geometry are stored in the document's optional OCAF container 9.
The evaluated feature type is `component`; normal `CadMechanicalInstance` entries refer to that feature.
Repeated insertions of the same record revision share a definition. One OCAF transaction includes the
new definition, geometry, material snapshot when applicable, and occurrence. Ordinary undo/redo and
instance placement/joint tools remain in use. Existing document instances and joints are preserved.

Native `.djo` stores this data in OCAF; CAD JSON version 8 includes optional versioned component
definitions. Older documents without components continue to open. Designs reopen without the catalog,
Drive, original workbook or attached model file. Later library edits do not update existing designs
implicitly: record identity/revision and frozen source metadata remain reproducible.

**Attach CAD...** snapshots a compatible local `.step`, `.stp` or millimetre `.brep` solid. STEP length
units are transferred into OCCT millimetres. There are no seed manufacturer CAD files in the supplied
workbooks, only availability/source references. No models are automatically downloaded. Geometry is
stored as a BRep snapshot; manufacturer subassembly hierarchy, colors and physical material models
are not inferred from the STEP transfer.

## Custom parts

Select a designed solid in the CAD workspace, then choose **Save designed part...** in the library.
The dialog also permits choosing another document solid. Set name, category and description. Its exact
evaluated geometry is stored in the part's local frame, with source document/feature/revision and an
existing material snapshot when assigned. Source CAD geometry and parametric history are unchanged.
The custom component can then be inserted into another design without its source document.

Custom publishing stores an evaluated solid snapshot, rather than a live copy of its feature history.
Publishing an existing envelope keeps its approximation label. Publishing a complete assembly with its
joint/subassembly structure is not included in this foundation; the dialog publishes individual solids.

## Engineering integration

Inserted parts support existing assembly composition, placement, body/face selection, exports, joint
authoring and fixture source references. Existing material assignments are imported through the same
document material system; no material properties are invented from a product name.

Fixture mass evaluation can sum published component masses and self-weight. Published mass does not
establish its centre of gravity or inertia, and is not changed by a fixture material substitution.
Those quantities remain unknown. Envelope volume is geometric information, never a substitute for
physical material volume. A custom solid with an explicitly assigned homogeneous material uses the
existing density-based mass evaluation. Kinematic use still requires authored joints. Product ratings
do not add a solver; the bounded cantilever backend continues to reject unsupported component geometry.

## Acceptance walkthrough

1. Open Component Library and expand Electrical / Battery packs.
2. Search `BLF-1203W`; inspect Bioenno's source attribution, 12 V, 3 Ah, 0.4 kg and 75 x 39 x 72 mm envelope.
3. Insert at zero placement; change X to 200 mm and insert a second occurrence.
4. Open CAD Workspace to inspect/select the two assembly occurrences and edit their normal placements.
5. Save as `.djo`, reopen and confirm two instances refer to one component definition with source metadata.
6. Design/select a solid, publish it under Custom, create another document and reuse that custom component.

Diagnostics: `--cad-component-check --research-root "G:/My Drive/000 DjehutiCAD"` exercises actual workbook
imports and core integration. Without `--research-root` it checks the offline bundled seed and core
integration. It exports the production-normalized seed to `build/component-library-seed.generated.json`.
`--cad-component-ui-check` exercises JUCE component wiring and saves a layout image, which excludes native
OpenGL pixels. `--cad-workspace-check` checks CreationDock registration/activation/float/dock.
`--cad-component-native --component-library <test JSON path>` opens the real docked CAD/library workspaces
in an isolated native diagnostic window without programmatic control invocation.
